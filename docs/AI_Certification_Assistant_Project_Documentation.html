01 — Executive overview

What the project does

The AI Certification Exam Assistant is a grounded learning system that converts repository-controlled certification knowledge into new practice-only multiple-choice questions, evaluates learner answers, detects weak areas, recommends official resources, builds a study plan, and calculates readiness through transparent rules.

4Certification-scoped FAISS indexes
30Passing Python tests
Official JSONCertification source of truth
RAGClean, chunk, embed, retrieve
OpenAIStructured grounded questions
FastAPIAuth, orchestration, persistence
ReactAssessment and learner insights

Core outcome: official certification knowledge → semantic retrieval → grounded practice → deterministic evaluation → personalized preparation.

Current production-candidate corpus

AWS Certified AI Practitioner (AIF-C01) contains five domains and fourteen detailed, source-linked topic/task chunks. It is the only corpus currently enabled for live question generation.

Reliability-first behavior

When retrieved content is incomplete, the system returns insufficient_context or blocks generation. It does not fill knowledge gaps with internet content or unsupported model knowledge.

02 — Scope

Goals, users, and boundaries

Primary goals

  • Generate new practice questions from retrieved official content.
  • Keep certification retrieval isolated before vector search.
  • Return machine-readable, validated question JSON.
  • Score MCQs without using an LLM.
  • Turn results into weak areas, official recommendations, study plans, and readiness.
  • Expose the proven AI foundation through a modular API and responsive learner interface.

Explicit content policy

  • Certification JSON files are the source of truth.
  • No leaked or real exam questions are used.
  • No random web content is added at runtime.
  • Generated items are always marked practice_only=true.
  • Source chunk IDs and official URLs must be preserved.
  • Unsupported certification corpora remain disabled.

03 — Architecture

End-to-end system design

Runtime request sequence

  1. A signed-in learner selects certification, difficulty, question count, and study-plan days.
  2. FastAPI checks that the selected corpus is detailed enough for question generation.
  3. The retriever selects the certification-specific FAISS index before embedding and searching the query.
  4. Retrieved chunks are sent to the AI Engine, which generates a strict Pydantic question batch.
  5. Deterministic and semantic grounding checks accept the batch or reject/regenerate it.
  6. FastAPI stores the assessment while keeping correct answers and explanations server-side.
  7. After submission, Python computes the score and all personalized outputs; SQLite stores the completed result.
  8. The React client renders results, sources, weak topics, plan, readiness, bookmarks, and history.

05 — Retrieval

RAG and vector database pipeline

Topic-aware chunking

One certification topic/task remains one semantic unit. Only unusually long topic content is split, using paragraph or sentence boundaries. The default maximum is approximately 3,500 characters with a small 250-character overlap. Each chunk receives a stable SHA-256-derived ID and retains all metadata.

Why this fits certification knowledge: exam guides are already organized into domains, tasks, and subtopics. Preserving those units avoids mixing unrelated objectives and gives each generated question a precise topic and source trail.

Embedding and index design

Embedding providerOpenAI Python SDKModeltext-embedding-3-small
Vector dimension1,536MetricCosine similarity through L2-normalized inner product
FAISS indexIndexFlatIPPersistenceGlobal index, metadata manifest, and per-certification indexes

Pre-search certification isolation

retrieve_context(query, certification_id="aif-c01", top_k=5)
    ↓
Resolve vector_store/by_certification/aif-c01.faiss
    ↓
Embed the query with the same stored embedding model
    ↓
Search only AWS positions and return text, domain, topic, source, score

An unknown certification ID is rejected before the query embedding call. An AWS selection therefore cannot retrieve Microsoft, IBM, Google, or DeepLearning.AI chunks.

Persisted RAG artifacts

  • data/rag_chunks.json — cleaned, validated semantic chunks.
  • vector_store/index.faiss — global inspection index.
  • vector_store/metadata.json — model, dimensions, chunk metadata, index mappings.
  • vector_store/by_certification/*.faiss — certification-scoped search indexes.

06 — Intelligence layer

OpenAI AI Engine

The AI Engine uses the OpenAI Responses API and Pydantic Structured Outputs. The generation model is configurable with OPENAI_GENERATION_MODEL and currently defaults to gpt-5-mini.

OpenAI-assisted functions

  • Grounded practice-question generation.
  • Closed-book semantic grounding review.
  • Optional explanation wording for weak areas.
  • Optional recommendation wording.
  • Optional study-plan wording.
  • Optional readiness explanation.

Deterministic functions

  • Answer and assessment scoring.
  • Domain and topic accuracy.
  • Weak-topic thresholds and priority.
  • Allowed source URL enforcement.
  • Study-plan topic/day structure.
  • Readiness score and classification.

Question output contract

{
  "question": "...",
  "options": {"A":"...", "B":"...", "C":"...", "D":"..."},
  "correct_answer": "A",
  "explanation": "...",
  "difficulty": "medium",
  "certification": "AWS Certified AI Practitioner",
  "domain": "...",
  "topic": "...",
  "source_chunk_ids": ["chunk_..."],
  "source_urls": ["https://official-source.example/..."],
  "practice_only": true
}

Generation acceptance gates

  1. Context must contain detailed explanatory content and an official URL.
  2. Every context record must match the requested certification.
  3. Exactly four distinct options and the requested question count are required.
  4. Domain, topic, chunk IDs, and URLs must exist in cited retrieved records.
  5. Every option, the answer, and explanation must pass deterministic grounding checks.
  6. A separate model call performs strict semantic entailment review.
  7. A failed batch may be regenerated with validator feedback, up to three attempts.
  8. If a reliable batch cannot be produced, the API returns an error instead of unsupported questions.

08 — Application services

FastAPI backend and SQLite database

FastAPI is a thin orchestration and persistence layer over the tested certification_assistant package. AI rules are not duplicated in route handlers. Pydantic request/response schemas reject unexpected fields and invalid ranges.

Backend responsibilities

API

Authentication, certification catalog, assessment generation/submission, result views, dashboard, bookmarks, and history.

Security

Argon2 hashes, JWT HS256 bearer tokens, active-user validation, CORS configuration, and ownership filters.

Orchestration

Corpus readiness guard, RAG call, AI generation, deterministic analytics, persistence, and public answer-key filtering.

Application database schema

TableImportant fieldsRelationship and purpose
usersid, email, full_name, hashed_password, is_active, created_atUnique email identity. One user owns many assessments and bookmarks.
assessmentsid, user_id, certification, difficulty, questions_json, answers_json, result_json, weak_areas_json, study_plan_json, readiness_json, statusStores the complete learner workflow. Foreign key to users with cascade delete.
bookmarksid, user_id, question_key, certification_id, question_json, noteUser-owned saved practice questions. Unique per user/question pair.
Two different databases serve different purposes: FAISS stores vector knowledge for retrieval; SQLite stores accounts and learner activity. They should not be presented as the same database component.

Privacy of assessment answers

Before submission, the public assessment schema excludes correct_answer and explanation. These fields remain in the server-side assessment record and appear only in the post-submission question review.

10 — Trust

Reliability, grounding, and safety controls

Knowledge controls

  • Repository JSON is the only knowledge source.
  • Certification-scoped search occurs before retrieval.
  • Embedding model compatibility is checked against the index manifest.
  • Generation is disabled for topic-label-only corpora.
  • Official URLs are allowlisted from retrieved content.

Question controls

  • Strict Pydantic Structured Output.
  • Exact four-option contract.
  • Practice-only flag enforcement.
  • Duplicate question detection.
  • Option, answer, and explanation grounding.
  • Independent semantic audit and safe failure.

Application controls

  • Argon2 password hashes.
  • Signed expiring bearer tokens.
  • Assessment ownership checked by user ID.
  • Correct answers hidden pre-submission.
  • Environment-based secrets and thresholds.

Transparency controls

  • Source chunk IDs and URLs preserved.
  • Deterministic scores and readiness.
  • Corpus readiness warning displayed.
  • Results can be reviewed question by question.
  • Unsupported generation returns an explicit error.
Important quality statement: passing automated checks is a quality gate, not a guarantee that every future model output is correct. Grounding metrics, rejected batches, and user feedback should continue to be monitored.

Recommended collaboration workflow

  1. Create a short issue with owner, inputs, expected output, and acceptance tests.
  2. Change only the owning subsystem unless an integration contract also requires an agreed update.
  3. Keep JSON schemas, Pydantic schemas, and frontend API expectations synchronized.
  4. Run local subsystem tests before requesting review.
  5. Use a small integration fixture for routine work; use live OpenAI only for defined smoke tests.
  6. Document corpus changes and vector-index rebuilds together.
  7. Do not commit .env, API keys, local SQLite records, or temporary demo credentials.

15 — Demonstration

Quick team demo through one public URL

For a temporary team demonstration, keep FastAPI on local port 8000 and expose only Vite port 5173. The Vite proxy forwards browser requests from /api to the local backend.

  1. Start backend on 127.0.0.1:8000.
  2. Start frontend on 127.0.0.1:5173.
  3. In VS Code, open the Ports view.
  4. Forward port 5173.
  5. Set Port Visibility to Public.
  6. Copy the generated https://...devtunnels.ms address and share it with the team.
  7. Stop forwarding after the demonstration.

What every tester can do

  • Create a separate learner account.
  • Generate an AWS AIF-C01 practice assessment.
  • Submit answers and receive an isolated result.
  • Review sources, weak areas, recommendations, study plan, readiness, history, and bookmarks.
  • Open the same public HTTPS URL from desktop, tablet, Android, or iPhone.
Demo limitations: the host laptop and both servers must stay running; anyone with the public link can reach the application; all OpenAI usage is charged to the configured project key; simultaneous live generations can be slower or encounter provider rate limits. This tunnel is not a production deployment.
